# ESTAS-AQUABC: Paper vs. Code vs. Constant Reference — Cross-Validation Analysis

**Date:** February 2026  
**Paper:** Ertürk, A., Sakurova, I., Zilius, M., Zemlys, P., Umgiesser, G., Kaynaroglu, B., Pilkaitytė, R. & Razinkovas-Baziukas, A. (2023) *Development of a pelagic biogeochemical model with enhanced computational performance by optimizing ecological complexity and spatial resolution.* Ecological Modelling, 486, 110509. doi:10.1016/j.ecolmodel.2023.110509.  
**Code Version:** Current `main` branch of ESTAS-AQUABC  
**Constant File:** `INPUTS/WCONST_04.txt` (323 constants)  
**Constant Reference PDF:** `docs/AQUABC_Constant_Reference.pdf` (generated by `tools/generate_constant_reference_pdf.py`)

---

## Executive Summary

This document presents a systematic cross-validation of three sources:

1. **The published paper** (Ertürk et al. 2023) — the primary model description
2. **The Fortran source code** — the actual implementation
3. **The constant reference PDF** — our generated documentation with literature references

The analysis reveals that the paper describes a **simplified configuration** of a substantially more complex model. The code contains 32 state variables (vs. 21 in the paper), 323+ constants (vs. 183 in the paper), and several biogeochemical modules (Fe/Mn redox, methane/H₂S, Nostocales life cycle, allelopathy) that are not discussed in the paper. We also identify reference gaps, naming discrepancies, and areas where the constant reference PDF should be updated.

### Analysis

The paper describes only the "core" 21-variable configuration used for the Curonian Lagoon case study. The additional 11 state variables are implemented in the code but were either:
- **Deactivated** for the published simulation (Fe/Mn/S/CH₄ redox via `ADVANCED_REDOX_OPTION` flag)
- **Added after publication** (Nostocales life cycle states)
- **Not discussed** because they represent optional modules

**Recommendation:** The constant reference PDF correctly documents parameters for all 32 state variables. A note should be added clarifying which state variables and parameter categories were active in the published configuration.

## 3. Process Implementation Verification

### 3.1 CTMI Temperature Model ✅ CONFIRMED

| Aspect | Paper | Code | Constant Reference PDF | Match |
|---|---|---|---|---|
| Formula | Rosso et al. (1993) CTMI | `GROWTH_AT_TEMP` subroutine | Documented as CTMI | ✅ |
| T_min = OPT_TEMP_LR | Implied | Confirmed (line 56) | Documented | ✅ |
| T_opt = OPT_TEMP_UR | Implied | Confirmed (line 57) | Documented | ✅ |
| T_max = KAPPA_OVER_OPT_TEMP | Implied | Confirmed (line 58) | Documented | ✅ |
| KAPPA_UNDER_OPT_TEMP unused | Not mentioned | Accepted but unused | Documented | ✅ |

**Reference verification:** Both the paper and our PDF cite Rosso et al. (1993). Our PDF additionally cites Bernard & Rémond (2012) for validation — this is appropriate and not contradicted by the paper.

### 3.2 N₂ Fixation ✅ CONFIRMED

| Aspect | Paper | Code | Match |
|---|---|---|---|
| Inverse Monod switching | "N2-fixation by cyanobacteria" | `K_FIX / (K_FIX + DIN)` | ✅ |
| R_FIX scalar | Implied | `R_FIX * growth_rate` | ✅ |
| Triggered at low DIN | "TDN < 0.8 mg/L" (Fig. 8) | `K_FIX = 0.008` half-sat | ✅ |
| DON included in DIN pool | Not explicit | `NH4 + NO3 + frac_avail_DON*DON` | ⚠️ Code adds bioavailable DON |

**Finding:** The code includes a `frac_avail_DON` fraction of DON in the available nitrogen pool for fixation switching. The paper does not explicitly mention this. The constant reference PDF does not call this out.

**Recommendation:** Add note to Nitrogen-Fixing Cyanobacteria category in the constant reference about DON bioavailability influence on fixation switching.

### 3.3 Hypoxia Stress ✅ CONFIRMED

| Aspect | Paper | Code | Constant Reference PDF | Match |
|---|---|---|---|---|
| Equation form | "hypoxia stress on organisms" | `THETA^(EXPON*(DO_thr - DO))` | Correctly documented | ✅ |
| Three regimes | Not detailed | Normal / stress / near-anoxic crash | Partially documented | ⚠️ |
| EXPON units L/mg O₂ | Not specified | Dimensional analysis confirms | Correctly documented | ✅ |

**Finding:** The code implements a three-regime hypoxia response:
1. **Normal** (DO > threshold): FAC_HYPOX = 1.0
2. **Stress** (0.1 < DO/threshold ≤ 1.0): exponential amplification of death rate
3. **Crash** (DO/threshold ≤ 0.1): special numerical safeguard that caps mortality and zeros growth/respiration

The constant reference PDF documents regimes 1 and 2 but not the crash regime. The paper only mentions "hypoxia stress" generically.

**Recommendation:** Expand hypoxia stress description in the constant reference to document all three regimes.

### 3.6 Zooplankton Prey Switching ✅ CONFIRMED

| Aspect | Paper | Code | Constant Reference PDF | Match |
|---|---|---|---|---|
| Variable stoichiometry | "tracking variable stoichiometry" | Zoo-C, Zoo-N, Zoo-P tracked separately | Documented (indices 10–12) | ✅ |
| Active switching | Not mentioned | Power-law switching (n=1.5) | Documented with note: "power 1.5" | ✅ |

**Finding:** The code has 6 prey types including Nostocales, but the paper only mentions 4 phytoplankton groups. This is consistent with Nostocales being an extension not in the paper's configuration.

**Finding:** The switching power of 1.5 is **hardcoded** (not configurable via WCONST). Our constant reference documents this as a characteristic but it's not a tuneable constant.

### 3.7 Nostocales Life Cycle ⚠️ NOT IN PAPER

| Aspect | Paper | Code | Constant Reference PDF | Match |
|---|---|---|---|---|
| Akinete germination | Not mentioned | T > T_GERM_AKI AND DIN < KN_GERM_AKI | Documented | N/A |

| Two Nostocales states | Not mentioned | Vegetative+heterocyst, Akinetes | Documented | N/A |

**Analysis:** The Nostocales life cycle module (akinete germination/formation, density-dependent mortality) is a significant model extension not covered in the paper. The paper mentions Hense and Beckmann (2010) in Table 2 as a model that "includes a growth cycle model of a single cyanobacteria group with multiple compartments representing the life cycle" — this is exactly what the Nostocales module implements, but the paper doesn't claim that AQUABC includes this. The module was likely developed after or concurrently with the paper.

## 5. Naming and Terminology Discrepancies

| Aspect | Paper Terminology | Code/Constant File | Impact |
|---|---|---|---|
| Non-fixing cyanobacteria | [Cyn-C]NOFIX | `CYN_C_INDEX` | Low — clear mapping |
| Fixing cyanobacteria | [Cyn-C]FIX | `FIX_CYN_C_INDEX` | Low — clear mapping |
| Other phytoplankton | [OPA-C] | `OPA_C_INDEX` | None |
| Nostocales vegetative | Not mentioned | `NOST_VEG_HET_C_INDEX` / `FIX_CYN_HET_C_INDEX` | ⚠️ Two different names in code |
| Nostocales akinetes | Not mentioned | `NOST_AKI_C_INDEX` / `FIX_CYN_AK_C_INDEX` | ⚠️ Two different names in code |
| Temperature params | Not explained | `OPT_TEMP_LR` = T_min (confusing name) | ⚠️ "LR" suggests "Lower Range" not minimum |
| | | `OPT_TEMP_UR` = T_opt (confusing name) | ⚠️ "UR" suggests "Upper Range" not optimum |
| | | `KAPPA_OVER_OPT_TEMP` = T_max | ⚠️ Name suggests decay rate, is actually T_max |

**Finding:** The CTMI parameter naming is counter-intuitive:
- `OPT_TEMP_LR` ("optimum temperature lower range") is actually **T_min** (minimum for growth)
- `OPT_TEMP_UR` ("optimum temperature upper range") is actually **T_opt** (the true optimum)
- `KAPPA_OVER_OPT_TEMP` sounds like a Kappa rate but is actually **T_max** (maximum for growth)
- `KAPPA_UNDER_OPT_TEMP` is accepted but **unused**

Our constant reference PDF correctly documents this mapping. This is an important finding because anyone reading the constant file without the reference document would likely misinterpret these parameters.

## 8. Recommendations

### 8.1 Constant Reference PDF Updates

1. **Add configuration notes**: Each category in the PDF that covers "extended" features (Fe/Mn, CH₄/H₂S, Nostocales, multi-EA anaerobic pathways) should include a note: *"This module was not active in the Ertürk et al. (2023) Curonian Lagoon configuration but is available for future applications."*

2. **Add Zilius et al. (2018)** as a calibration data reference in relevant categories (Diatoms, N-Fixing Cyanobacteria, Zooplankton): *Zilius, M. et al. (2018) The influence of cyanobacteria blooms on the attenuation of nitrogen throughputs in a Baltic coastal lagoon. Biogeochemistry, 141(2), 143–165.*

3. **Expand hypoxia stress documentation**: Document all three regimes (normal, stress, crash) with the exact equations.

4. **Add DON bioavailability note**: In the N₂ Fixation section, note that `frac_avail_DON` fraction of DON is included in the pool that controls fixation switching.

5. **Clarify CTMI naming confusion**: Consider adding a prominent note or FAQ explaining why `OPT_TEMP_LR` ≠ "lower optimal temperature" but rather T_min, etc.

6. **Add hardcoded constants note**: Document key hardcoded values not in WCONST (zooplankton switching power = 1.5, CO2SYS K1K2 = 4, etc.).

7. **Update Chapra reference**: Consider citing both Chapra (1997) *and* Chapra (2008) since the paper cites the latter.

### 8.2 Code Documentation Improvements

1. **Nostocales naming inconsistency**: The code uses both `FIX_CYN_HET_C_INDEX` and `NOST_VEG_HET_C_INDEX` for the same state variable. Standardise to one convention.

2. **CTMI parameter naming**: Consider adding inline comments in the Fortran read statements clarifying the actual CTMI role of each parameter (already partially done in `aquabc_II_pelagic_auxillary.f90` but not in the parameter reading code).

3. **`nconst` vs actual count**: `nconst = 318` in `mod_GLOBAL.f90` but 323 constants exist (extras loaded by name). Document this discrepancy.

### 8.3 Potential Paper Errata / Notes

1. **State variable count**: Paper says 21 but code has 32. The paper clearly states this was the configuration for the Curonian Lagoon case study, not the full model capability. This is not an error but could be clarified in future publications.

2. **Constant count**: Paper says 183 but the calibrated configuration likely had more active constants. The "183" may refer to only those constants that were actually varied during calibration.

3. **Hense & Beckmann reference**: Paper cites (2010) in Table 2; our PDF cites (2006). Both are correct — the 2006 paper introduced the akinete model, the 2010 paper extended it. Both should be cited.

## 10. Conclusion

The ESTAS-AQUABC model as implemented in code is substantially more complex than the configuration described in Ertürk et al. (2023). This is by design — the paper presents a specific application (Curonian Lagoon 2015) using a subset of the model's capabilities. The constant reference PDF correctly documents the full model, including extended modules. The literature references in the PDF are appropriate parameter-level citations that complement rather than duplicate the paper's reference list.

The primary actionable findings are:
1. The constant reference should clearly distinguish "core" parameters (used in the published configuration) from "extended" parameters (available but not used in the paper's case study)
2. Zilius et al. (2018) should be added as a key calibration reference
3. Minor documentation gaps exist for the hypoxia crash regime, DON bioavailability in fixation switching, and hardcoded model constants
4. The CTMI parameter naming convention is a persistent source of confusion that should be prominently documented

All core model equations described in the paper are correctly implemented in the Fortran code and accurately documented in the constant reference PDF. No fundamental discrepancies between the paper's scientific content and the code implementation were found.
