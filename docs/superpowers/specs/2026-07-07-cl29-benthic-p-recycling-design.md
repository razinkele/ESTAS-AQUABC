# CL29 Benthic Phosphorus Subsidy — Design Spec

**Date:** 2026-07-07 (rev. 2, after adversarial review loop)
**Status:** 🪦 SUPERSEDED — never implemented. The prescribed-benthic-flux approach was rejected in favour of full sediment diagenesis (lineage `3dc7e53`→`274c45c`); the external-P-subsidy idea later resurfaced as the boundary-PO4 lever (`CL29_BOUNDARY_PO4_SUMMER_PEAK`), not this flux machinery. Kept as historical record only.
**Goal:** Add a measurement-anchored benthic phosphorus source to the CL29 (Curonian
Lagoon, 29-box) AQUABC application so the P-supply-limited spring diatom bloom can
approach observed magnitudes, using the model's existing prescribed-sediment-flux
machinery driven entirely from the converter — no Fortran changes.

> **Rev-2 note.** A three-lens review (codebase-correctness, implementation-gaps,
> scientific-soundness) reshaped this spec. The biggest changes: (1) honest reframing
> from "seasonal recycling delivering spring P via carryover" to an **external,
> net-positive P subsidy anchored on measured fluxes**; (2) the flux **does** couple
> into TOT_ALK/CO2SYS (not stability-free); (3) fluxes are **signed** (sandy spring is
> a sink); (4) several robustness gaps and upgraded guardrails. Two decisions remain
> flagged for the user (§13).

## 1. Background & motivation

The CL29 spring diatom bloom undershoots observations ~2× (domain peak 24.6 vs observed
47 ± 14 mg/m³ Chl-a; Bartoli et al. 2018). Process-rate diagnostics
(`docs/CL29_Parameter_Validation.md`) root-caused this as **phosphorus-supply
limitation, system-wide**: `LIM_P ≈ 0.29` dominant, PO4 drawn to <0.014 mg/L,
N/Si/light/grazing non-binding, no box reaching the observed floor. A P-boost
perturbation (IC PO4 0.010→0.05, river ×2) lifted spring diatoms 19.6→29.0 and domain
max to 42.7 with `LIM_P` pinned — confirming P supply as the ceiling. A structural gap:
`MODEL_SEDIMENTS = 0`, so there is no benthic P source at all.

**Scientific framing (revised).** Published work on *this* lagoon (Zilius et al. 2012;
Petkuviene et al. 2016; Zilius et al. 2013) shows benthic P release is a **summer,
redox/hypoxia-driven feedback that self-sustains the cyanobacterial bloom** — SRP
efflux peaks in July on muddy sediments, while sandy sediments are a spring/light-season
P **sink** (benthic-microalgal uptake). The Nemunas Feb–April flood coincides with the
diatom build-up and flushes the northern basin (renewal ~77 d north, ~200 d south;
Umgiesser et al. 2016). Therefore a benthic PO4 flux does **not** cleanly deliver P to
the spring diatom window; its spring benefit is indirect (a modestly elevated background
P pool, strongest in the stagnant south) while its direct effect is on summer. We
therefore treat this intervention honestly as an **external, measurement-anchored P
subsidy** whose primary defensible justification is that the lagoon's sediments are a
real net P source the current model omits — not as a mass-conservative recycling term.
The confirmation test already showed that adding P (even as a steady background) lifts
spring diatoms; this spec grounds that addition in measured benthic fluxes.

## 2. Approach

**Chosen: prescribed benthic PO4 flux** (`MODEL_SEDIMENTS = 1`,
`NUM_PRESCRIBED_SEDIMENT_FLUX_SETS = 1`). A per-box, seasonally varying PO4 flux (signed:
+ release, − uptake) drawn from a forcing time series and added to the water-column PO4
mass balance by existing solver code. No Fortran changes; all artifacts generated by the
converter.

**Rejected alternatives:**
- *Full sediment diagenesis* (`MODEL_SEDIMENTS > 1`): mechanistically complete and
  mass-conservative, and it would natively couple N+P and redox — but high-effort (author
  `BOTTOM_SEDIMENT_MODEL_INPUT.txt` + 171-constant `W_SED_CONST.txt` for CL29), slowest,
  CO2SYS-stability-risky, and mutually exclusive with resuspension. Deferred as a larger
  future project; it is the "right" long-term answer if the subsidy proves too crude.
- *Resuspension option 1*: injects resuspended pore-water/particulate concentration, not a
  diagenetic flux — wrong conceptual tool.

## 3. Architecture & data flow

All new logic is in the converter (`tools/eutropy_poc/eutropy_to_estas.py`) and its
generated `INPUTS_CL29/`. PO4 is pelagic state variable **3** (`PO4_P_INDEX = 3`,
`aquabc_II_pelagic_svindex.f90:8`).

```
User-supplied tables (converter)                 ESTAS runtime
┌─────────────────────────────┐   generate
│ CL29_SEDIMENT_TYPE          │ ─────────────►  INPUTS_CL29/
│ CL29_BENTHIC_PO4_FLUX       │                   ├─ BENTHIC_FLUX_TS.txt             (forcing TS #15)
└─────────────────────────────┘                   ├─ PRESCRIBED_SEDIMENT_FLUXES.txt  (29×36 = 1044-row map)
                                                   ├─ PELAGIC_INPUTS.txt  (NUM_FORCING_TS 14→15)
                                                   └─ INPUT_CL29.txt      (MODEL_SEDIMENTS 0→1,
                                                                           NUM_PRESCRIBED_SEDIMENT_FLUX_SETS 0→1)
```

**Runtime path (verified against source):**
- Parsed in `mod_AQUATIC_MODEL.f90:459-493` (`MODEL_SEDIMENTS`→`MODEL_BOTTOM_SEDIMENTS`;
  full diagenesis is `> 1`, value 2 selects it; `NUM_PRESCRIBED_SEDIMENT_FLUX_SETS` read
  only under `== 1`).
- Map read by `sub_READ_BOTTOM_SEDS_FLUXES_INPUTS.f90` (two header lines, then exactly
  `NUM_BOXES × NUM_STATE_VARS` rows, indexed by each row's own BOX/STATE fields).
- Per timestep the flux is assembled from the forcing TS at `mod_SOLVER.f90:640-659`,
  the **`SURFACE_AREAS(i) × PRESCRIBED_SEDIMENT_FLUXES(i,j)`** product is formed in
  `CALC_DERIV` at **`mod_SOLVER.f90:1254-1263`**, and that term is **summed into
  `tot_deriv` and integrated** at **`mod_SOLVER.f90:157-166`** (RK2 paths `:344-351`,
  `:387-391`). Positive → PO4 mass increase (release).
- **Single-layer precondition:** for boxes with an underlaying box the derivative is
  scaled by `(SURFACE_AREAS − BOTTOM_AREAS)/SURFACE_AREAS` (`mod_SOLVER.f90:1269-1277`).
  CL29 has one box per basin (`UNDERLAYING_PELAGIC_BOX = 0` for all), so the plain
  `area × flux` formula holds and mmol/m² is against the box surface footprint. The plan
  must assert single-layer boxes; if CL29 ever stacks layers this silently rescales.

## 4. Converter data structures (user-editable)

Two module-level tables, mirroring the existing `CL29_WCONST_OVERRIDE` pattern:

```python
# box (1..29) -> sediment type. Omitted box or 'none' = zero flux for that box.
CL29_SEDIMENT_TYPE = { 1: 'sand', 2: 'mud', ..., 29: 'sand' }

# seasonal benthic PO4 flux per sediment type, mmol P / m2 / day.
# 12 monthly values (Jan..Dec). SIGNED: positive = release, negative = uptake
# (sandy spring is typically an uptake/sink; muddy summer a strong source).
CL29_BENTHIC_PO4_FLUX = {
    'mud':  [ ...12 signed values... ],
    'sand': [ ...12 signed values... ],
}
```

**Required converter validation** (mirror `_apply_wconst_overrides`' fail-fast style):
- error if any non-`'none'` sediment type lacks a key in `CL29_BENTHIC_PO4_FLUX`;
- error if any flux list length ≠ 12;
- error if any box key ∉ 1..29;
- warn (not error) on an unused flux key.

## 5. Generated / modified artifacts

One new converter function (`_write_benthic_flux(out, tdays)`), called from `main()`,
plus small conditional edits to `_write_master`/`_write_input_txt`.

1. **`BENTHIC_FLUX_TS.txt`** — forcing TS #15 via the existing `write_ts`. Columns in
   deterministic order: **column 1 = zero**, then one column per sediment type in sorted
   key order (stable per-type column index). Values are the 12 monthly flux numbers,
   converted mmol→g P (×0.03097; 30.97 g/mol) so units are g P/m²/day; TS SCALE and
   UNIT-CONVERSION header rows stay 1.0 (matches `write_ts` and `mod_TIME_SERIES.f90`
   which multiplies both, so 1.0 passes the g-values through). **Time axis = the exact
   `tdays` array from `main()`** (indices 0..1826 = 2012-01-01 .. 2016-12-31); month per
   day is computed with real dates (`date(2012,1,1)+timedelta(days=idx)).month`) so leap
   years (2012, 2016) don't drift the seasonal signal.
2. **`PRESCRIBED_SEDIMENT_FLUXES.txt`** — the 29×36 = 1044-row map. Header: two lines.
   The converter iterates **boxes 1..29** (missing key ⇒ `'none'`) × **all 36 state
   vars**, emitting exactly one row per pair (missing pairs would cause an out-of-bounds
   `FORCINGS(0,0)` read in the solver, so completeness is mandatory; assert 1044 rows):
   - PO4 rows (`STATE_VAR_NO = 3`): `FORCING_TS_NO = 15`, `FORCING_TS_VAR_NO =` the box's
     sediment-type column (or 1 = zero column if `'none'`).
   - all 35 other state vars: `FORCING_TS_NO = 15`, `FORCING_TS_VAR_NO = 1` (zero column).
3. **`PELAGIC_INPUTS.txt`** — `NUM_FORCING_TS` 14→15; append `BENTHIC_FLUX_TS.txt` to the
   converter's `ts_files` list (currently 14 entries).
4. **`INPUT_CL29.txt`** — `MODEL_SEDIMENTS` 0→1; `NUM_PRESCRIBED_SEDIMENT_FLUX_SETS` 0→1;
   name `PRESCRIBED_SEDIMENT_FLUXES.txt` on the `SEDIMENT MODEL INPUT FILE` line.

**Opt-in / off by default.** If `CL29_SEDIMENT_TYPE` is empty (or all `'none'`), the
converter emits **none** of the above, keeps `NUM_FORCING_TS = 14`, leaves
`MODEL_SEDIMENTS = 0`, and leaves the trailing bare `# SEDIMENT MODEL INPUT FILE` header
with no filename — so output is byte-identical to today's baseline.

**Testability refactor.** So the wiring can be asserted without a destructive `main()`
run (which `rmtree`s and writes into `os.getcwd()`), thread the sediment toggle,
`NUM_FORCING_TS`, and `NUM_PRESCRIBED_SEDIMENT_FLUX_SETS` through `_write_master` /
`_write_input_txt` as parameters and let them accept an output-directory argument; keep
the `CL29_*` tables monkeypatchable.

## 6. Units, sign, seasonality

- **Units:** input mmol P/m²/day → g P/m²/day via ×0.03097, done explicitly in Python.
  (The internal pelagic mass unit is grams; the sediment path does **not** apply the
  ×1000 the mass-load path uses, so `area[m²] × g P/m²/day` = g P/day is consistent.)
- **Sign:** signed values; positive = release, negative = uptake. Sandy spring months are
  typically negative (a real sink; Zilius et al. 2012); muddy summer months strongly
  positive.
- **Seasonality:** 12 monthly values per type, tiled across all years via real-date month
  mapping, interpolated by ESTAS.

## 7. Caveats (scientific)

- **This is an external subsidy, not conservative recycling.** The flux is not fed by
  deposition nor drawn from a finite pool. It is a net loading term justified by measured
  net sediment–water exchange. Do **not** claim mass conservation; monitor drift (§9).
- **Spring benefit is indirect.** Benthic P peaks in summer and the spring flood flushes
  the north, so most direct benefit is to summer; the spring diatom lift comes via a
  modestly higher background/pre-bloom P pool, strongest in the stagnant southern boxes.
  Expect summer cyano to respond first. This is why success is evaluated per-box at the
  observation station and across all years, and why the flux magnitude will need
  calibration within the measured envelope (§9, §13).
- **Net-positive vs net-zero — resolved.** A net-zero annual flux (summer release exactly
  balanced by winter uptake) would add no net P and would sit spring at the
  post-winter-uptake minimum, defeating the goal. We therefore accept a **net-positive**
  subsidy and monitor multi-year drift explicitly (§9), rather than forcing annual
  balance. (These are the same transport: strong flushing both limits drift and limits
  carryover.)
- **N:P coupling risk.** Real Curonian benthic release is coupled N+P (NH4 efflux rises
  Mar→Oct). Adding P **only**, applied year-round, lowers summer DIN:DIP and can favor the
  N-fixing cyanobacteria (Aphanizomenon, Dolichospermum, Nostocales) that dominate this
  lagoon's summer bloom — inflating summer cyano and/or suppressing non-fixers. Mitigation
  is a mandatory summer DIN:DIP guardrail (§9); the `CL29_BENTHIC_*` structure is built to
  accept a coupled NH4 table with no schema change if the guardrail trips (§13 decision).
- **Alkalinity/CO2SYS coupling — this flux is NOT stability-free.** The prescribed PO4
  flux is also passed into `PELAGIC_KINETICS` as `SEDIMENT_FLUXES` and drives
  `PO4P_SEDIMENT_INFLUX → ALK_LOST_BY_PHOSPHATE_GEN → TOT_ALK` derivative
  (`aquabc_II_pelagic_model.f90:3373-3530`; `CONSIDER_ALKALNITY_DERIVATIVE` hardcoded 1).
  A release is an alkalinity sink; uptake an alkalinity source. TOT_ALK feeds CO2SYS,
  which this converter already had to hand-stabilize (INORG_C=3.0/TOT_ALK=3.1). So the
  subsidy perturbs pH; validation must watch CO2SYS convergence and pH/ALK/DIC (§8).
- **Scope.** PO4 primary. Benthic Si omitted (huge spring margin; verify DISS_Si floor
  stays ≫ KHS_DSi). Benthic NH4 is a live extension, gated by the §9 N:P guardrail.

## 8. Validation & testing

- **Python unit test** (`tests/python/`), no ESTAS run — enabled by the §5 testability
  refactor: with fixture tables, assert the map has exactly 1044 rows (boxes 1..29 × 36
  states, each once); PO4 rows point to the correct sediment-type column; all 35 non-PO4
  vars point to the zero column; a `'none'`/omitted box's PO4 row points to the zero
  column; TS values equal input ×0.03097; month mapping is leap-year-correct; and the
  wiring flags flip (`MODEL_SEDIMENTS 1`, `NUM_PRESCRIBED_SEDIMENT_FLUX_SETS 1`,
  `NUM_FORCING_TS 15`, flux TS listed). Also assert the fail-fast validations (§4).
- **Regression:** empty tables → converter output diffed against a pre-change snapshot of
  `INPUTS_CL29/` + `INPUT_CL29.txt` is byte-identical (pin the off-path invariants in §5).
- **Clean-checkout:** the pipeline still builds and runs from a fresh clone.
- **Full run:** 5-yr completes ("simulation finished"), **no NaN, no CO2SYS
  non-convergence, and no `NEGATIVE MASS PREDICTED` for PO4** (a negative flux that
  exceeds a box's PO4 would be silently re-floored at MIN_CONCENTRATION —
  `mod_SOLVER.f90:207-212` — so bound uptake ≤ available PO4 or assert the warning never
  fires).

## 9. Success criteria & guardrails

Evaluate at **box 19** (the reference/observation station used throughout the docs) and
an area-weighted domain mean, and **report all 5 years** (not just the 5-yr mean).

- **Primary:** box-19 spring diatom Chl-a moves materially toward 47 ± 14 mg/m³ (from
  today's 19.6), using the user's measured fluxes.
- **Guardrails:**
  - summer cyano stays within 96 ± 56 mg/m³ **and** the spring:summer Chl ratio stays
    near the observed ~0.5 (47/96) — a tighter joint check than the wide band alone;
  - diatom→OPA→cyano succession preserved (order **and** timing of peaks);
  - **water-column DIP realism:** spring and summer PO4 stay within observed Curonian
    ranges (don't hit the diatom target by driving PO4 unrealistically high);
  - **summer DIN:DIP realism** (catches the N-fixer artifact of PO4-only enrichment);
  - **no interannual PO4 drift:** annual-mean PO4 changes <~10% from year 2→5, checked
    hardest in the stagnant southern boxes;
  - DISS_Si floor stays ≫ KHS_DSi (0.013); other boxes/groups not degraded.
- **Mechanistic check:** box-19 process rates show `LIM_P` relaxing, or biomass rising
  with `LIM_P` pinned (resource-limitation signature).

## 10. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Summer-peaked flux boosts cyano more than spring diatoms | Reframed as subsidy; evaluate both seasons + spring:summer ratio; calibrate within measured envelope |
| PO4-only lowers summer DIN:DIP → N-fixer inflation | Mandatory DIN:DIP guardrail; coupled-NH4 extension ready (§13) |
| Multi-year PO4 drift (net-positive external source) | Quantitative drift guardrail (§9), stagnant-south checked hardest |
| Alkalinity/CO2SYS perturbation → pH non-convergence | Watch CO2SYS convergence + pH/ALK/DIC in full-run validation; keep flux within measured envelope |
| Negative (uptake) flux hits MIN_CONCENTRATION floor | Bound uptake ≤ available PO4; assert no NEGATIVE-MASS-PREDICTED for PO4 |
| Silent rescale if CL29 ever gains stacked layers | Assert single-layer (one box per basin) precondition |

## 11. Out of scope / future extensions

- Coupled benthic NH4 (and Si) fluxes on the same 29×36 map (structure ready; gated by
  the N:P guardrail).
- Full sediment diagenesis (`MODEL_SEDIMENTS > 1`) — a separate, larger, mass-conservative
  project; the right answer if the subsidy proves too crude.
- Concentration/deposition-feedback flux (only the full model provides this).

## 13. Decisions flagged for the user

1. **N:P coupling.** Recommended: ship **PO4-only** with a mandatory summer DIN:DIP
   guardrail, and enable a coupled benthic **NH4** flux (same table structure) only if the
   guardrail trips. Alternative: add the coupled NH4 flux from the start (more realistic
   N:P, slightly more data + one more TS column). Which do you want?
2. **Framing/ambition.** Recommended: proceed with the honest **external P subsidy**
   (calibrated within your measured envelope), accepting that spring benefit is partly
   indirect. Alternative: if you consider that too crude for a mechanistic spring answer,
   we reconsider the **full diagenesis model** (`MODEL_SEDIMENTS > 1`) as a separate,
   larger effort. Proceed with the subsidy?
