# CL29 Benthic Phosphorus Recycling — Design Spec

**Date:** 2026-07-07
**Status:** Design (approved), pending implementation plan
**Goal:** Add benthic (sediment) phosphorus recycling to the CL29 (Curonian Lagoon,
29-box) AQUABC application so the P-supply-limited spring diatom bloom can reach
observed magnitudes, using the model's existing prescribed-sediment-flux machinery
driven entirely from the converter — no Fortran changes.

---

## 1. Background & motivation

The CL29 spring diatom bloom undershoots observations ~2× (domain peak 24.6 vs
observed 47 ± 14 mg/m³ Chl-a; Bartoli et al. 2018). Process-rate diagnostics
(`docs/CL29_Parameter_Validation.md`) root-caused this as **phosphorus-supply
limitation, system-wide**: `LIM_P ≈ 0.29` dominant, PO4 drawn to <0.014 mg/L,
N/Si/light/grazing non-binding, and no box reaches the observed floor. A Redfield
mass-balance check and a direct P-boost perturbation confirmed the P budget supplies
only ~half the P needed. A key structural gap is that **`MODEL_SEDIMENTS = 0`** — there
is no benthic P regeneration, which in a shallow hypertrophic lagoon is a major internal
P source.

This spec adds that source in the cheapest defensible way: a prescribed benthic PO4
flux parameterized from measured Curonian Lagoon sandy/muddy sediment fluxes.

## 2. Approach

**Chosen: prescribed benthic PO4 flux** (`MODEL_SEDIMENTS = 1`,
`NUM_PRESCRIBED_SEDIMENT_FLUX_SETS = 1`). A per-box PO4 release rate, drawn from a
seasonal forcing time series, added directly to the water-column PO4 mass balance by
existing solver code. No Fortran changes; all artifacts generated by the converter.

**Rejected alternatives:**
- *Full sediment diagenesis* (`MODEL_SEDIMENTS = 2`): mechanistically complete
  (24 sediment vars × 7 layers/box, deposition→mineralization→redox release,
  mass-conservative) but high-effort (author `BOTTOM_SEDIMENT_MODEL_INPUT.txt` +
  171-constant `W_SED_CONST.txt` for CL29), slowest path, CO2SYS-stability risk, and
  mutually exclusive with resuspension. Over-engineered for the goal (YAGNI). Remains
  a viable future project if deposition-coupled sediments are ever needed.
- *Resuspension option 1*: can inject PO4 but models resuspended pore-water/particulate
  concentration, not a diagenetic flux — conceptually the wrong tool.

## 3. Architecture & data flow

All new logic is in the converter (`tools/eutropy_poc/eutropy_to_estas.py`) and its
generated `INPUTS_CL29/`. PO4 is pelagic state variable **3** (`PO4_P_INDEX = 3`).

```
User-supplied tables (converter)                 ESTAS runtime
┌─────────────────────────────┐   generate
│ CL29_SEDIMENT_TYPE          │ ─────────────►  INPUTS_CL29/
│ CL29_BENTHIC_PO4_FLUX       │                   ├─ BENTHIC_PO4_FLUX_TS.txt         (forcing TS #15)
└─────────────────────────────┘                   ├─ PRESCRIBED_SEDIMENT_FLUXES.txt  (29×36 = 1044-row map)
                                                   ├─ PELAGIC_INPUTS.txt  (NUM_FORCING_TS 14→15)
                                                   └─ INPUT_CL29.txt      (MODEL_SEDIMENTS 0→1,
                                                                           NUM_PRESCRIBED_SEDIMENT_FLUX_SETS 0→1)
                                                          │
              mod_SOLVER.f90:157-166 ◄──────────────────┘
              ECOL_PRESCRIBED_SEDIMENT_FLUX_DERIVS(box, PO4=3)
                  = SURFACE_AREAS(box) × PRESCRIBED_SEDIMENT_FLUXES(box, 3)
              tot_deriv += that term  →  new_mass = old_mass + tot_deriv·dt
```

Each timestep ESTAS reads the box's PO4 flux from the seasonal TS (interpolated),
multiplies by box surface area, and adds it to the PO4 derivative. Sandy vs muddy boxes
reference different TS columns; the seasonal signal lives in the TS time axis.

Reference code paths (read-only, verified): input parse in
`mod_AQUATIC_MODEL.f90:459-493`; map reader `sub_READ_BOTTOM_SEDS_FLUXES_INPUTS.f90`;
flux assembled `mod_SOLVER.f90:640-659`; applied to derivative `mod_SOLVER.f90:157-166`
(also RK/Euler paths `:344-351`, `:387-391`).

## 4. Converter data structures (user-editable)

Two module-level tables, mirroring the existing `CL29_WCONST_OVERRIDE` /
`CL29_PHYTO_REFUGE` pattern:

```python
# box (1..29) -> sediment type. 'none' (or omission) = no benthic flux for that box.
CL29_SEDIMENT_TYPE = { 1: 'sand', 2: 'mud', ..., 29: 'sand' }

# seasonal benthic PO4 release per sediment type, mmol P / m2 / day.
# 12 monthly values (Jan..Dec); positive = release to the water column.
CL29_BENTHIC_PO4_FLUX = {
    'mud':  [ ...12 values... ],
    'sand': [ ...12 values... ],
}
```

The user supplies both tables from measured Curonian data. Sediment-type keys are
open-ended (`'mud'`, `'sand'`, or others) as long as every non-`'none'` value in
`CL29_SEDIMENT_TYPE` has a matching key in `CL29_BENTHIC_PO4_FLUX`.

## 5. Generated / modified artifacts

One new converter function (`_write_benthic_p_flux(out, tdays)`), called from `main()`,
produces/edits four files; the `INPUT_CL29.txt` and `PELAGIC_INPUTS.txt` writers gain a
few conditional lines.

1. **`BENTHIC_PO4_FLUX_TS.txt`** — forcing TS #15, written via the existing `write_ts`.
   Columns in deterministic order: **column 1 = zero**, then one column per sediment
   type in sorted key order (e.g. `mud`, `sand`), giving each type a stable column
   index. Monthly values tiled across the 2012–2017 daily time base (day-of-year →
   month), converted mmol→g P (×0.03097) so values are g P/m²/day (TS unit-conversion
   factors stay 1.0).
2. **`PRESCRIBED_SEDIMENT_FLUXES.txt`** — the 29×36 = 1044-row map. Header: two lines.
   Each row `BOX_NO STATE_VAR_NO FORCING_TS_NO FORCING_TS_VAR_NO`:
   - PO4 rows (`STATE_VAR_NO = 3`): `FORCING_TS_NO = 15`, `FORCING_TS_VAR_NO = ` the
     column index of that box's sediment type (or the zero column if `'none'`).
   - all 35 other state vars: `FORCING_TS_NO = 15`, `FORCING_TS_VAR_NO = 1` (zero column).
3. **`PELAGIC_INPUTS.txt`** — `NUM_FORCING_TS` 14→15; append `BENTHIC_PO4_FLUX_TS.txt`
   to the forcing-TS filename list (converter `ts_files`, currently 14 entries).
4. **`INPUT_CL29.txt`** — `MODEL_SEDIMENTS` 0→1; `NUM_PRESCRIBED_SEDIMENT_FLUX_SETS`
   0→1; the `SEDIMENT MODEL INPUT FILE` line names `PRESCRIBED_SEDIMENT_FLUXES.txt`.

**Opt-in / off by default.** If `CL29_SEDIMENT_TYPE` is empty (or every box is
`'none'`), the converter emits none of the above and leaves `MODEL_SEDIMENTS = 0`, so
the current baseline is byte-for-byte unchanged until real data is supplied.

## 6. Units, sign, seasonality

- **Units:** input mmol P/m²/day → g P/m²/day via ×0.03097 (P molar mass 30.97 g/mol),
  done explicitly in Python (not in the TS header).
- **Sign:** positive = release to water column (inverts the muddy/sandy template
  convention, where negative = uptake).
- **Seasonality:** 12 monthly values per type, tiled across all years, interpolated by
  ESTAS. Note the timing tension in §7.

## 7. Caveats

- **Seasonal timing vs the spring target.** Benthic P release is temperature-driven and
  typically peaks in summer, low in spring — when diatoms most need P. The spring diatom
  benefit therefore comes mainly via *carryover*: summer/autumn release enlarges the
  standing P pool that persists through winter into the next spring (the P-boost test
  confirmed a larger pre-bloom pool lifts spring diatoms). Expect summer cyano to respond
  first, spring diatoms second. Validation must watch both seasons.
- **Mass balance.** A prescribed flux is an external P source, not fed by deposition or
  drawn from a finite sediment pool. Measured *net* fluxes (release minus uptake, with
  negative winter values) keep the annual budget realistic, but multi-year PO4 drift must
  be checked; if P accumulates, the measured winter uptake balances it.
- **Scope.** PO4 only. Benthic NH4 and Si fluxes are real and measured but N and Si are
  replete in the spring diatom window, so they are out of scope (YAGNI). The 29×36 map
  structure makes adding them later a small extension.

## 8. Validation & testing

- **Python unit test** (`tests/python/`) for the converter, no ESTAS run required:
  with a small fixture `CL29_SEDIMENT_TYPE`/`CL29_BENTHIC_PO4_FLUX`, assert the map has
  1044 rows; PO4 rows point to the correct sediment-type column; all 35 non-PO4 vars
  point to the zero column; TS values equal input ×0.03097; `INPUT_CL29` shows
  `MODEL_SEDIMENTS 1` / `NUM_PRESCRIBED_SEDIMENT_FLUX_SETS 1`; `PELAGIC_INPUTS.txt` shows
  `NUM_FORCING_TS 15` with the flux TS listed.
- **Regression:** empty tables → `MODEL_SEDIMENTS 0` → generated inputs byte-identical to
  the current baseline.
- **Clean-checkout:** the pipeline still builds and runs from a fresh clone (as secured
  in `docs/CL29_Parameter_Validation.md` work).
- **Full run:** 5-yr completes with "simulation finished", no NaN.

## 9. Success criteria & guardrails

- **Primary:** with the user's measured fluxes, domain spring diatom Chl-a moves into the
  observed 33–61 mg/m³ band (from today's 2.3–24.6).
- **Guardrails:** summer cyano stays within 96 ± 56 mg/m³ (no overshoot); the
  diatom→OPA→cyano succession is preserved; no interannual PO4 drift; other boxes and
  phytoplankton groups are not degraded.
- **Mechanistic check:** box-19 process rates show `LIM_P` relaxing, or biomass rising
  with `LIM_P` pinned (the resource-limitation signature from the P-boost test).

## 10. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Summer-peaked flux boosts cyano more than spring diatoms | Use measured spring/winter rates; validate both seasons; rely on carryover |
| Multi-year PO4 accumulation (external source) | Use net measured fluxes; check drift; measured winter uptake balances |
| Over-enrichment → cyano/OPA overshoot | Calibrate within the measured range against the guardrails |
| Numerical stability | Negligible — prescribed flux is a table lookup + multiply; no CO2SYS |

## 11. Out of scope / future extensions

- Benthic NH4 and Si fluxes (trivial map extension when wanted).
- Full sediment diagenesis (`MODEL_SEDIMENTS = 2`) — a separate, larger project.
- Concentration- or deposition-feedback on the flux (only the full model provides this).
